# Session Transcript Export Backends

Load only when choosing, running or troubleshooting an export method. Prefer the platform's own full-transcript export; fall back to the scripts only when no suitable capability exists. Every export script redacts secrets automatically after writing (`redact_secrets.py`). Run scripts with `-B` (or set `PYTHONDONTWRITEBYTECODE=1`) so no `__pycache__` lands in the repo.

## Hermes

When Hermes sessions are stored in a SQLite database:

```bash
python3 scripts/export_transcript.py --list --date <YYYY-MM-DD>
python3 scripts/export_transcript.py --session <session_id> -o <output.md>
```

Default database is `~/.hermes/state.db`. When the schema changes, inspect the tables read-only first; never modify the original database.

**Find the session id with `scripts/find_session.py` first** (it queries state.db directly, so results are deterministic and unaffected by FTS tokenization): `--latest` for the current or most recent session, `--days N` to list sessions in a window, `--grep <keyword>` to find a session by LIKE over message text. The active session does not appear in `export_transcript.py --list`; find it this way too.

- **session_search is FTS5; long Chinese words and hyphenated terms silently return 0 hits** (tested 2026-11-06): `'巨幅石刻壁画'` returned 0; `'G2-2'` was parsed as column-filter syntax, errored and was swallowed as 0; `'州桥'` did hit. So 0 hits ≠ the session doesn't exist; confirm with `find_session.py --grep` or SQL LIKE before concluding. If you must use it, search only short 2–4 character words likely separated by punctuation.
- **Do not filter on `active = 1`:** context compression marks old messages `active = 0`, but they are still real original text (filtering on active kept only 34 of 162 messages in one test). Exclude only `_compressed_summary = 1` (AI summaries generated by compression). Use `--active-only` only when you really want just the current context.
- Context rebuilds re-insert whole blocks of history. The script de-duplicates: runs of 3+ identical messages in identical order are dropped as a block; repeated long assistant texts keep only the first. User messages are not globally de-duplicated (sending "1" twice is real conversation). The header records how many of each were dropped.

## Claude Code

```bash
python3 scripts/export_jsonl_transcript.py --list --agent claude --date <YYYY-MM-DD>
python3 scripts/export_jsonl_transcript.py --agent claude --session <session_id> -o <output.md>
```

Looks for JSONL in `~/.claude/projects/` by default, and also in `$CLAUDE_CONFIG_DIR/projects/` and `~/.claude-*/projects/`. When the machine has several configurations (for example `CLAUDE_CONFIG_DIR=~/.claude-2`), the header's source-file line shows which one the session came from.

User messages inserted mid-run are stored as `attachment.type=queued_command`; the script includes them in time order (cross-session messages from other windows are filtered). Context-compression summaries (`isCompactSummary`) are dropped. The header notes record how many of each.

## Codex

```bash
python3 scripts/export_jsonl_transcript.py --list --agent codex --date <YYYY-MM-DD>
python3 scripts/export_jsonl_transcript.py --agent codex --session <rollout path or unique fragment> -o <output.md>
```

Looks for rollout JSONL in `~/.codex/sessions/YYYY/MM/DD/` by default. If the current platform offers native thread reading or export, prefer it to avoid depending on internal formats.

## WorkBuddy

```bash
python3 scripts/export_workbuddy_transcript.py --list
python3 scripts/export_workbuddy_transcript.py --list --date <YYYY-MM-DD> --project "<working-directory fragment>"
python3 scripts/export_workbuddy_transcript.py --session <session_id> -o <output.md>
```

Sessions live at:

```
~/.workbuddy-ai/projects/<encoded working directory>/<sessionId>.jsonl
```

Encoding rule: every `/` and space in the absolute path becomes `-`.

Differences from Claude Code / Codex:

- **The active session does appear in `--list`**; take its sessionId and export directly.
- Timestamps are **milliseconds**, not seconds.
- User messages carry a large environment injection; the real user input is inside `<user_query>...</user_query>`. The script takes user_query first, otherwise strips `system-reminder` and similar tags.
- One jsonl mixes `message` / `reasoning` / `function_call` / `function_call_result` / `session-meta` / `file-history-snapshot` / `ai-title`; only `message` is original text.

## DSH (DeepSeek Harness)

```bash
node scripts/export_dsh_session.js <session.v4.jsonl.zstd> <raw.jsonl>
python3 scripts/export_dsh_transcript.py <raw.jsonl> <transcript.md> [session id] [working dir] [frame count]
```

- Session location: `~/.dsh/sessions/<workspace dir name>/<session-id>/session.v4.jsonl.zstd`. The current session id is in the `DSH_SESSION_ID` environment variable.
- The session file is **multi-frame concatenated zstd**. `zstdDecompressSync` decodes only the first frame (a 1.37 MB file yielded 237 bytes); decompress frame by frame in a loop, which the script does. Tested: 1.37 MB → 914 frames → 1493 JSONL lines → 88 visible messages.
- Event types: `user/message` (data.content[].text), `assistant/message` (data.message.content[].text; filter the reasoning and tool-call parts inside); tool/result, request/* and step/* are never exported.

## Failure handling

- When the user asks for an export, do not give up because the session is still active. Every backend can export an active session; try this page's way of finding it first. If all fail, report honestly what range you got and mark it "pending re-export".
- Session not found: list candidates and check date, platform and working directory.
- Several matches: never guess silently; narrow to a unique id.
- Format changed: inspect record-type distribution with `--inspect <file>` first, then change the parser.
- Cannot export completely: report the range obtained and mark it "pending re-export"; never produce a fake transcript.
