# 文件夹整理规则：模式选择 + 归档规范

> 借鉴：claude-obsidian 的 wiki-mode（模式选择而非强制模板）+ PARA 的项目/归档边界思想。
> 原则：**让目录自己长，但长得不歪。** 不硬套模板，不打乱自然生长的结构。

## 一、模式选择（三种，选一个作为主模式）

| 模式 | 适用 | 结构 | 你现在的系统 |
|---|---|---|---|
| **项目制**（推荐默认） | 项目数量少而清晰（<30个），每项目一个目录 | 顶层=项目目录，项目内自由生长 | ✅ 当前模式 |
| PARA轻量 | 项目多到顶层放不下，需要"活跃/非活跃"分流 | 顶层分 Projects/Areas/Resources/Archive | 备选 |
| 类型制 | 项目属性雷同（全是某种产出） | 按类型分：成稿/素材/数据 | 备选 |

**规则**：
- 主模式只影响"新东西往哪放"，**绝不批量迁移现有目录**
- 切换模式 = 单独操作，先预览再执行，用户拍板
- 不要混用：顶层结构保持一种模式

## 二、五条整理原则（项目制模式下）

### ① 一个文件夹 = 一个项目
- 有3个以上关联文件的主题 → 建文件夹，散落的归进去
- 反例：根目录躺着 `李大魔的精力管理问题.md`，而 `写手李大魔&李大魔多元思维/` 存在 → 孤儿，应归位

### ② 项目文件夹命名
- 用项目名，**不带日期/版本号/序号前缀**（版本在文件里 V1/V2，日期在文件名里）
- 避免同名多目录：一个项目一个真源目录（如 `开怀精选美女专题/` 唯一）
- 反例：`10_精选美女专题/`（旧）与 `开怀精选美女专题/`（新）并存 → 旧的进归档

### ③ 根目录只留活跃文件
- 根目录散落文件 > 10个 = 待归位信号（用 scan.py 检查）
- 历史决策 → 项目目录或 `决策事件/`
- 旧版本 → 归档目录
- 新收材料 → `_收件箱/`，处理完归位

### ④ 归档目录统一规范
```
项目/
├── _归档/              ← 统一命名（或"归档/"，一个系统内保持一致）
│   └── 旧方向_YYYY-MM-DD/   ← 按归档原因+日期分块
│       └── （原样保留，不重组）
```
- 归档块名说明"为什么归档"（旧方向/已完结/被V2取代）
- 归档内容原样保留，不做二次整理（省维护成本）

### ⑤ 同名跨位置 = 重复信号
- 同名文件跨目录：内容相同 = 冗余副本（删一个）；不同 = 版本分叉（判定真源，旧的删或标明）
- 同名目录跨位置：diff 内容+时间戳，判定正式版；旧的标"旧工作副本"待用户确认
- 判定规则：修改时间新 + 内容完整度高（有README/结构全）= 正式版

## 三、扫描检查项（scan.py 自动做）

| 检查 | 信号 | 处置 |
|---|---|---|
| 无README目录 | 有文件但无README.md | 补索引 |
| 根目录散落 | >10个文件 | 出待归位清单 |
| 同名文件跨目录 | 内容相同/不同 | 删副本/判真源 |
| 同名目录跨位置 | 存在多处 | 判正式版 |
| 空目录 | 0文件0子目录 | 删（用户确认） |
| 目录内同名文件 | 大小写不同 | 确认是否有意 |

## 四、与四问的关系

folder-rules 是四问第①问（住哪层）在**文档层内部**的展开：
- 住哪层？→ Memory/文档/Skill（SKILL.md 主入口）
- 住哪个文件夹？→ 本文件（项目归属、归位、归档）

## 五、Pitfall

- **不硬套模板**：claude-obsidian 支持四种模式让用户选，就是这个原因——PARA 对写作型创作者不友好（Reddit 反馈），项目制更适合
- **不批量迁移**：切模式/改名/移动都只影响未来，现有文件动了容易断指针（8.28 飞书误覆盖的教训同源）
- **不全局编号**：Johnny.Decimal 的编号对 AI Agent 场景收益低（Agent 用 README+搜索找东西），只在归档/素材等易堆积目录用前缀可选
