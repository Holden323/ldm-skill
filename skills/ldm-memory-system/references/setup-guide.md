# 阶段一：搭建工作流

> 从零搭建认知资产系统，或系统混乱时重建。2026-08-28 重构版，统一四问框架。

## 适用场景

- 新用户第一次搭建记忆系统
- 老用户系统混乱：无索引、无分类、不知道哪些该升级成skill
- 用户说「搭建记忆系统」「从零开始搭」「我的记忆很乱，重新搭一遍」

## 前置准备

1. 加载本skill（ldm-memory-system）作为裁判
2. 读取当前 memory 全部条目（如果有）
3. 了解用户的项目结构（读README、看目录）

## 第一步：三问摸底

向用户问3个问题（回答决定分层和毕业判断）：

```
① 你有哪几个长期项目？
   → 决定文档层怎么分文件夹
② 哪些文件最常被引用？
   → 决定哪些要建索引（README/章节）
③ 哪些操作反复做过3次以上？
   → 决定哪些该毕业成skill
```

用户回答不完整时，从现有文件推断（README、目录结构、skill列表），不强迫用户逐项回答。

## 第二步：画三层结构图

用**用户自己的项目举例**，不用通用模板。示例格式：

```
第3层 Skill（操作手册）
  ├─ <技能A>：<它解决什么>
  └─ <技能B>：<它解决什么>

第2层 文档系统（项目资料库）
  ├─ <项目A>/
  │   ├─ README.md（目录索引）
  │   └─ <关键文档>.md（##章节）
  └─ <项目B>/

第1层 Memory（随身小本子，~2000字符）
  ├─ 铁律：<规则1> / <规则2>
  ├─ 进度：<数字1> / <数字2>
  └─ 指针：<指向文档X> / <指向skill Y>
```

## 第三步：建文档层

按项目建文件夹，每个目录一个README：

```
项目文件夹/
├── README.md        # 这个文件夹里有什么、先读哪个
├── 文档A.md         # 长文档必须有 ## 章节标题（grep可检）
└── 素材/            # 素材子目录
```

规范：
- 每个文件夹（>1个文件）必须有README
- 长文档（>100行）必须有 ## 章节标题
- 版本号命名V1/V2/V3，不覆盖旧版（本地+云端都存档）
- 新建文件/目录后顺手更新README

## 第四步：建Memory层

清点现有条目（如果有），按四问归类：

| 判定结果 | 动作 |
|---------|------|
| 该住当前层（Memory）| 保留，B级格式重写 |
| 重复（与其他条目内容重叠）| 进待删除单（给用户拍板）|
| 该住更低层（详情进skill/文档）| 进待降级单（给用户拍板）|
| 涉及外部token/计数/路径 | 进指针验证单（当场验证）|

写入铁律：
- 用B级格式：结论 + 关键数字 + 推导逻辑概要
- 一行一条，§分隔
- 不存完整API key（真源在配置文件）
- 不存完整路径（真源在文档/配置）
- 不存对话原文（真源在聊天存档）
- 写入前先问：这条会不会被纠正？会 → 放能被纠正的那层

## 第五步：定毕业标准

明确"什么内容该升级成skill"，4条同时满足：

```
① 重复性：同一流程出现过3次以上
② 换人能跑：别人/别的Agent拿到也能执行
③ 有触发条件：能写清楚"什么时候该用它"
④ 用户确认：用户亲口说"这个以后常做"
```

把用户已有的"反复做的操作"列出来，逐条判断是否满足。不满足 → 留在文档层。

## 第六步：试跑验证

搭完跑一次维护扫描（见 scan-workflow.md），确认：

- 每个指针指向的文件存在
- 每个目录有README
- memory条目分类清晰、无重复
- 用户能回答"我的XX信息在哪"这样的问题

## 最小可行版（怕复杂的新用户）

只做前三步，文档层和skill层用到再建：

1. Memory分类：把现有条目按铁律/进度/指针归类
2. 根目录README：入口文件→项目目录→工具→存档→快速导航
3. 走一次维护扫描验证

不强制一次搭完。系统能跑起来比"完整"重要。

## 注意事项

- 搭建期间可能有并发更新（其他session同时改文件），操作前重新读取
- 删除/降级操作必须给用户拍板，不能自己判断自己删
- 验证指针时用只读操作（fetch/stat/ls），不要修改任何外部数据
- 搭完把本次的新坑写进SKILL.md的踩坑记录本
