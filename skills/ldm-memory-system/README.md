# ldm-memory-system（记忆系统）

## 它帮你解决什么问题？

你的 AI 助手有个记忆空间，还会存文档、存 skill、存各种路径和 token。时间一长就乱成一锅粥：

- **记忆只进不出**：塞满了只能删，删了又忘
- **指针过期没人管**：记的飞书链接早失效了，还躺在那占地方
- **规则多副本打架**：同一条规矩，memory 一份、文档一份、skill 一份，改了一个忘了另一个
- **不知道东西该放哪**：该进 skill 的流程留在文档里，该留一行指针的详情塞进 memory，全乱了

## 以前有什么问题，现在改了？

**以前**：只有"清理记忆"一个动作（断舍离），而且只管 memory，不管文档和 skill——等于打扫了客厅，厨房卧室还是乱的。

**现在**：一套框架管所有类目——memory 条目、文档、skill、指针，全用同一个"四问"过一遍：

```
① 住哪层？    这该放 Skill / 文档 / Memory 哪层？
② 真源在哪？  唯一正本是哪个文件？其他都是复印件/路标？
③ 还准吗？    指向的东西还在吗？数字还对吗？
④ 有索引吗？  所在目录有 README 吗？长文档有章节标题吗？
```

四问一过，该留的留、该删的删、该搬家的搬家，条条有下落。

## 它会怎么帮你干活？

**搭建**（第一次用 / 系统乱了）：
先问你三个问题（有哪些长期项目？哪些文件最常被引用？哪些操作反复做过？），然后按你的实际情况搭三层结构——skill 手册、项目文档、随身记忆，各就各位。

**维护**（日常/定期）：
扫描所有内容过四问 → 产出三张清单（该删的 / 该降级的 / 指针失效的）→ **给你过目，你说删才删** → 执行完汇报改了多少。

## 核心规则（三句话）

1. **Memory 是指针，不是数据库**——完整内容住文档/skill，memory 只留导航
2. **一条知识只能有一个正本**（SOT 唯一真源），其他层最多留指针，不许平行开副本
3. **删东西永远你拍板**——Agent 只出清单，不做决定

## 和别的 skill 怎么配合？

- `ldm-session-handoff`（交接）管"会话之间不丢进度"，本 skill 管"长期记忆不腐烂"
- 项目收尾（代码/文档对不上）是 neat-freak 的活，本 skill 不碰代码

## 什么时候该用？

- 说"清理一下 memory"
- 说"我的记忆系统好乱，帮我搭一下"
- 说"整理一下文档 / skill 太多了"
- 平时 Agent 往 memory 里写新东西时，按这里的写入规则执行
