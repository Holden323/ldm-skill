# 可读性检查（产线第 7 步）

> 分两遍执行：写作中「局部自检」+ 终稿「全量 QC」。
> QC 查的是 AI 味（风格），查不出理解成本（逻辑可及性）——风格过关 ≠ 读者能懂，两件事分开查。

## 第一遍：写作中局部自检（每段写完）

### 1. 外行复述测试

**读者把这段讲给家里人听，能说明白吗？** 说不明白就是缺解释层，缺的通常是五种之一：

1. **术语没翻译成生活动作**：先讲生活动作，再顺便给名字
   - ❌ 蜜罐测试，故意放一些AI不该碰的目标
   - ✅ 故意在环境里放诱饵，看它碰不碰，专门钓鱼用的，这就是蜜罐测试
2. **压缩表述被读者外推**（2026-09-08 小米芯片篇教训，读者留言抓出）：写「华为有自己的供应链体系和品牌溢价」，读者理解成「华为什么零件都自己造」，留言反驳「涨价的内存华子也不能造」。事实没错（华为的国产替代采购体系确实存在且有效），但「有供应链体系」四个字把「设计能力/制造能力/采购体系」三件事压成了一件，读者按自己的理解外推后就成了「事实错误」。
   - **铁律：技术能力表述必须拆环节——设计、制造、采购是三回事，写清楚这家公司具体强在哪一环。** 「有XX体系」「掌握XX能力」这类压缩断言，写之前问：读者会不会理解成更夸张的版本（全自造/全自研/100%）？会就拆开写。
   - 被读者质疑后的处置：先核实（对/错/部分对），事实没错的不要改稿，在留言区辨析讲清区别——留言区辨析比改正文更能建立可信度。
3. **因果链跳了一步**：中间步必须写出来，哪怕啰嗦
   - ❌ 先拆开关，再宣布达成
   - ✅ 宣布AGI=要付代价=亲手按开关 → 先把条款删了 → 再宣布
4. **数字没翻译成画面**：数字必须带分母+画面
   - ❌ 56%的测试会去碰
   - ✅ 一百次里有五十六次会伸手，一半多的概率，见到就想拿
5. **只有结论没有过程**：你读完素材「哇」的那个瞬间才是主体，不是可省的铺垫
6. **证据链缺中间步**（2026-09-04 Astra篇教训）：整段推理都对，但每一步之间的桥没铺
   - ❌ 说它没作弊的测试，OpenAI自己做的。说它安全的数据，OpenAI自己发布的。（逻辑悬空：自己做的怎么了？读者得自己脑补"不独立"这个前提）
   - ✅ 打个比方，一个员工闯过祸，两个月后他跟老板说我现在不偷懒了。怎么证明？他自己做了个测试，测完自己打了个分，把分数交给了老板。（每一步都铺了，读者不用脑补）

### 2. 逻辑搭桥三问（段落之间）

1. 上一段最后一句，和这一段第一句之间，有没有逻辑跳跃？
2. 读者读完上一段，能不能自然理解为什么要讲这一段？
3. 缺的那个承上启下的信息是什么？（通常一句话就够）

### 3. 手法时机自检（这段该用什么，而不是什么都用）

- 讲机制 → 用长句慢慢讲，别用短句跳
- 给结论 → 用短句钉死
- 有数据 → 带分母带画面
- 有画面 → 白描动作，别解释情绪

### 4. 事实序列 vs 类比自检（2026-09-04 Astra篇V2教训）

**事实本身够震撼时，类比是累赘，砍掉。**

用户把微软合同段的开关类比（90字）整段砍掉，只留事实顺序：「先删条款，再宣布达成」。又把导航类比整段砍掉。

判断标准：如果你把类比删掉，只留事实序列，读者还能感受到冲击吗？能 → 类比多余，砍。不能 → 类比有必要，保留，但用白话不用铺垫。

### 5. 逗号 vs 句号自检

- 论断和论断之间 → 句号
- 同一串连续动作、同一个解释内部 → 逗号连
  - ✅ 逃了出来，入侵了OpenAI的内部系统，然后搞到了互联网访问权限
  - ❌ 逃了出来。入侵了OpenAI的内部系统。然后搞到了互联网访问权限。（太碎）

## 第二遍：终稿全量 QC

### 6. 硬性扫描（机械执行）

| 检查 | 标准 |
|---|---|
| 重定语句 | 一句话超过35字且「的」超过3个时，检查是否真的难读；必要时拆分 |
| 破折号 | 特定栏目禁用；其他任务按用户文风判断 |
| 高频句式 | 不是…而是…/你以为…其实…重复出现时检查模板感；不得编造“我见过”“我身边有”等经历 |
| 书面连接词 | 本质上/值得注意的是/然而/此外密集出现时，删掉无功能的路标或换成自然衔接 |
| 广告术语 | 赋能/痛点/闭环/抓手/赛道/颗粒度与语境不符时改成具体动作 |
| 模型路标 | 更微妙的是/还有一层/只说对了一半若只在报幕，直接进入事实或判断 |
| 报幕腔 | 先看两个数字/还有一个细节没有推进作用时删除 |
| 兜底句 | 当然有个前提…等句式只在确有重要边界时保留 |

### 7. 人工判读（脚本查不出的）

**AI味的本质是「太完美」**：没有毛边、没有卡顿、没有跑题、没有任何一处是作者自己也没想通的。完美本身就是不真实的信号。

- 情绪曲线太光滑 → 不要伪造犹豫；保留真实存在的不确定性或未解问题
- 段落节奏太均匀 → 数五句，字数都差不多就打乱，加一句两三个字的
- 每个特征背后有用户的意图 → 改写不是删特征，是问「用户本来想达成什么」

**核心机制审查**：如果只能保留一件事，保留哪件？一段内容只能有一个核心机制，所有内容服务它。说了六件事=什么都没说清楚。找不到核心 → 「核心不明确」本身就是最大的问题。

**机制说了但没说清**：结论有了，但缺「因为所以」那句机制。读者只能「感觉对」，不能「突然明白了」。加一句「因为…所以」——机制只需要一句话。

**立场漂移检测**：开头站读者这边，中间变说教，结尾变教育 → 受众从「被代言」变「被说教」。确定一个立场，从头到尾只站一边。

### 8. 误报警告（别机械执行，人工判断）

| 特征 | 触发阈值 | 说明 |
|---|---|---|
| 不是X是Y | 800字内3次以上 | 低密度是正常修辞，鲁迅李敖也用 |
| 短句堆砌 | — | 口语化节奏可能是故意设计 |
| 单句成段 | — | 是常态，不是问题 |
| 段段金句 | 仅公众号长文 | 短视频/口播稿段段金句是体裁要求 |
| 替读者说蠢话 | 虚构读者声音被矮化 | 经典修辞，本身不是AI特征 |

## 结尾检查

- 删掉最后一段，文章完整吗？完整就说明结尾多余
- 结尾禁：总结全文/喊口号/升华主题/号召行动
- 结尾好收法：回环开头意象、留一个没回答的问题、克制的感受收尾
- 「不强制升华」——故事说清楚就让它自己结束
